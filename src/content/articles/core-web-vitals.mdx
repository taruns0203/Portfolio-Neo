## Start with the reading experience

A fast application helps people reach their goal without waiting for the interface to settle. For an editorial page, start with its most important content: the title, introduction, and first useful image. Keep that content available in the initial HTML, then add interaction where it serves the reader.

Core Web Vitals describe loading, responsiveness, and visual stability. Use field data to understand actual visits and lab tools to investigate a reproducible problem. A single local run is a diagnostic clue, not evidence of how every visitor experiences a website.

## Find the loading bottleneck

Inspect the network waterfall before changing code. Is the important image discovered late? Is a stylesheet delaying rendering? Is a large client bundle doing work before the page responds? Choose one hypothesis, make one targeted change, and repeat the same test conditions.

## Keep interaction work focused

Render static editorial content on the server. Give interactive controls small client boundaries: a copy button needs browser APIs; a paragraph does not. Measure expensive interactions before adding memoization or changing state management.

<Callout variant="tip">
  Test the interaction people actually perform. Opening a gallery, filtering a
  list, and navigating between pages exercise different parts of an application.
</Callout>

## Make delivery predictable

A cache can avoid repeated work, but its policy must match how often content changes and whether responses contain personalized data. Document invalidation alongside the cache itself. Verify both a cold request and a repeat visit.

## Verify the whole page

Check a narrow viewport as well as a large screen. Use the keyboard, increase text size, and enable reduced motion. Watch for clipped code, tables that widen the entire page, and media that shifts nearby text after loading.

## Keep a verification record

Record the route, device assumptions, test conditions, and the change you made. Separate reproducible lab observations from field measurements. Recheck accessibility and functionality after an optimization: a faster page that loses essential behavior is not a successful outcome.
